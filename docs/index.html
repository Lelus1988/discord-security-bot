Ein Sicherheitsbot,
der genau einen Server kennt.

Private Security-Bot ist ein modularer Discord-Bot für Whitelist-Server: Anti-Raid, Anti-Spam, vollständige Moderation, Ticket-System und ein Web-Dashboard, das live auf dieselbe Logik zugreift wie die Slash-Commands.

Installation ansehen Funktionen erkunden
bot@security — zsh
guild:main $
Probier: hilfe · status · features · whoami · clear
Funktionen

Was der Bot im Hintergrund macht

Jede Funktion läuft über dieselbe Service-Schicht, egal ob sie per Slash-Command oder über das Dashboard ausgelöst wird.

Whitelist-Enforcement

Der Bot verlässt automatisch jeden Server, der nicht in der Konfiguration eingetragen ist.

Owner-Präsenzprüfung

Verlässt den Server sofort, sobald die Owner-ID den Server verlässt, gekickt oder gebannt wird.

Anti-Raid

Join-Schwellenwert mit Scoring löst bei Überschreitung einen automatischen Lockdown mit Wiederherstellung aus.

Anti-Spam

Erkennt Nachrichtenrate, Wiederholungen, Mass-Mentions und Spam-Links, reagiert mit Auto-Mute und Löschung.

Rollen-Hierarchie-Check

Moderatoren können, auch über das Dashboard, niemals höher- oder gleichrangige Mitglieder sanktionieren.

Ticket-System

Vollständiger Ticket-Flow direkt über Slash-Commands, ohne externe Integration.

Eigene Server-Befehle

Pro Server konfigurierbare Text-Trigger im BotGhost-Stil, ohne Slash-Command-Redeploy.

Audit-Logging

Jede Aktion landet identisch in MongoDB und optional in einem konfigurierbaren Log-Kanal.

Web-Dashboard

Live-Mitgliederliste, Rollenverwaltung, Willkommensnachrichten, Regeln und Logs, abgesichert über OAuth2.

Setup

Installation

Fünf Schritte vom geklonten Repo bis zum laufenden Dashboard.

Abhängigkeiten installieren

Installiert discord.js, mongoose, express und alle weiteren Pakete aus package.json.

cd discord-security-bot
npm install

Discord Developer Portal einrichten

Server Members, Presence und Message Content Intent aktivieren, Redirect-URI eintragen.

Wichtig: Ohne die drei privilegierten Intents funktionieren Mitgliederliste, Online-Status und eigene Text-Befehle nicht.

Konfiguration anlegen

.env aus der Vorlage erzeugen und Token, IDs sowie MongoDB-URI eintragen.

cp .env.example .env

Slash-Commands registrieren und starten

Bot und Dashboard starten im selben Prozess mit Hot-Reload.

npm run deploy
npm run dev

Dauerbetrieb mit PM2 (optional)

Für Autostart und Absturz-Recovery ohne offenes Terminal.

npm install -g pm2
npm run build
npm run service:start
pm2 save
Design-Prinzip

Sicherheitsmechanismen

Dashboard und Slash-Commands teilen sich dieselbe Prüf-Logik, keine Aktion umgeht die Regeln.

Ein Server, eine Whitelist

Nur Server in ALLOWED_GUILDS sind erlaubt, alle anderen werden sofort wieder verlassen.

OAuth2-Zugriffskontrolle

Nur Discord-Nutzer mit "Server verwalten"-Berechtigung sehen oder bearbeiten einen Server im Dashboard.

Rollen-Hierarchie

Ein Moderator kann nie jemanden sanktionieren, der ranghöher oder gleichrangig ist, auch nicht über das Dashboard.

Durchgängiges Audit-Log

Jede Aktion aus Slash-Command oder Dashboard landet in MongoDB und optional im Log-Kanal.
